# EdgeTune

一个原生 macOS 音乐侧边浮窗原型。借鉴 Pulse 的贴边收起交互，界面与代码独立实现。

当前版本：**1.2**。

## 功能

- 316 × 110 像素的置顶浮窗；鼠标离开 1 秒后平滑收起，右侧保留 7 × 72 像素的主题色边缘
- 鼠标靠近原浮窗所在高度的屏幕右边缘，停留 0.2 秒后自动展开
- `⌥⌘M` 展开或收起；图钉可固定展开状态
- 在设置中选择网易云音乐、QQ 音乐、Spotify 或 Apple Music，查看歌曲信息并使用上一首、播放/暂停、下一首
- 设置登录 Mac 后自动启动（通过系统登录项管理）
- 设置中选择 5 种纯色或 3 种渐变主题，装饰条、收起边缘和歌词同步换色；选择自动保存
- 窗口主题可选黑色、白色和原生毛玻璃；文字与按钮自动适配，窗口主题与主题色独立保存
- 边缘条与展开后的装饰条根据所选播放器的实时音频强弱伸缩，暂停后恢复静态；设置中可关闭
- 网易云音乐和 QQ 音乐优先从各自曲库获取同步歌词及已有中文翻译，翻译与原文各显示一行；没有翻译时原文最多两行。匹配失败或接口不可用时回退 LRCLIB；其他播放器继续使用 LRCLIB
- 歌词与右侧按钮留出间距，长句最多显示两行；匹配到明确的纯音乐标记时显示“纯音乐，请欣赏”
- 菜单栏入口；不会占用 Dock

## 构建与运行

需要 macOS 14 或更新版本，以及 Apple Command Line Tools（提供 Swift 与 Clang 编译器）；无需 Node、Rust 或 Homebrew。构建时会从仓库内 `third_party/nowplaying-cli` 源码编译媒体适配工具。

```sh
chmod +x build.sh
./build.sh
open outputs/EdgeTune.app
```

歌词查询需要网络。媒体适配工具使用 macOS 私有的 MediaRemote 接口；系统更新后可能需要适配。它随应用一起构建，不需要额外安装。

节奏动画通过 ScreenCaptureKit 读取所选播放器的音频，需要允许系统的屏幕与系统音频录制权限。只在内存中计算音频强弱，不接收屏幕画面、不保存或上传音频。授权后会自动尝试重连；如系统要求退出并重新打开，请按提示重启。连接中断后会自动重连。开发构建使用固定代码签名身份，避免每次更新都改变系统识别的应用身份。动画反映实时音量变化，不进行 BPM 或拍点识别。

## 当前范围

### 开发签名与音频权限

开发构建现在必须使用固定签名身份，默认名称为 `EdgeTune Local Development`。可通过 `EDGETUNE_SIGNING_IDENTITY` 指定已有代码签名证书的完整名称。首次配置可在“钥匙串访问”的证书助理中创建同名的自签名代码签名证书，保存在登录钥匙串，并仅为代码签名用途设置信任。私钥只留在本机，不提交仓库；不要将证书设为所有用途始终信任。

从临时签名迁移后，需要为固定签名版本重新授予一次音频权限。之后保持证书、bundle ID 和安装路径一致，不要重新生成证书。构建脚本拒绝缺少证书、签名要求变化及覆盖正在运行的应用；先在临时目录完成编译和签名验证，再替换应用。`outputs/.signing-requirement` 保存签名要求，不应通过删除它绕过检查。

验证方式：播放网易云音乐，确认音频样本及边缘条变化；退出、构建、重启，连续两次确认无需重新授权且有新的音频样本。固定签名不能避免用户撤销权限、系统授权策略变化或播放器未输出音频。

需要排查时可用 `open -n --env EDGETUNE_AUDIO_DIAGNOSTICS=1 --stderr /tmp/EdgeTune-audio.log outputs/EdgeTune.app` 启动，日志每三秒记录音量区间，不保存音频。正常启动不启用此诊断。

2026-10-12 本机验证：从临时签名迁移后，先修改程序内容，再更新构建号，连续两次构建与重启均无需再次授权。两次 CDHash 分别为 `52471334be74a46cac03af528b2d2c95453b52e6` 和 `c9c02abc6dc3538a17decf9c0e4b9f1fd316e02d`，签名要求一致；两次都收到 connected、first sample 及持续变化的音量区间。运行中构建、缺少证书的构建均被阻止。

这是 macOS 原型，只在系统“正在播放”会话属于所选桌面客户端时显示和控制。播放器需要向 macOS 发布媒体信息；尚未完成各播放器的端到端验证。开机启动可能需要在系统设置的“登录项”中批准。Windows 版可复用歌词数据逻辑与界面方案，但系统媒体控制和浮窗需要单独实现与测试。
